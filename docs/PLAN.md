# FileHub — 需求分析与版本规划

## 一、需求分析

**背景**：局域网内多台 PC 之间要快速分享文件，但 Windows 共享目录经常因为
SMB 设置、账号密码、权限、防火墙等原因「找不到对方」。需要一个零配置、
点开即用的替代方案。

**核心诉求（帅兵）**：
1. Go 编译的单文件可执行程序，服务端口 `36774`，UI 走 Web。
2. 启动后 `upload` 目录 = 对外共享的文件；`download` 目录 = 下载落地目录。
3. 程序自动发现本网段内有哪些 IP 开放了这个服务，展示机器服务列表。
4. 点击某台机器可看到其 upload 目录的文件名、大小、日期等；可下载到自己的
   download 目录。下载前先比较是否是同一文件：没有就直接下，有就断点续传。
   展示下载进度、是否完成、文件 OK 还是损坏等状态。

**设计决策**：
- **发现机制**：UDP 广播（`36774`）。每个实例周期性广播 `{hostname, httpPort, version}`，
  同时监听广播构建机器列表，超时自动剔除离线节点。跨平台、零配置。
- **下载落地**：下载由「本机服务端」执行（浏览器只发指令），保证文件落在本机
  `download` 目录，而不是浏览器默认下载目录。
- **断点续传**：本地 `.part` 临时文件 + HTTP `Range` 请求；`http.ServeContent`
  原生支持 Range。
- **同文件判定**：文件名 + 大小 + SHA-256 三者一致才跳过下载（秒传）。
- **完整性校验**：下载完成后校验 SHA-256，不一致标记「损坏」。
- **进度/状态**：任务含 downloaded/size/speed/status，Web 轮询展示。

## 二、版本规划

| 版本 | 目标 |
|------|------|
| **v0.1.0** ✅ 已交付 | 单文件共享：机器发现、文件列表、单文件下载、断点续传、哈希校验、进度/状态展示 |
| **v0.1.1** ✅ 已交付 | 修复：元信息即时返回（不再等对方算哈希导致启动久等）；进度 0% 起点正确；新增下载暂停/继续/终止 |
| **v0.1.2** ✅ 已交付 | 支持 upload 子目录浏览（点击进入/返回上级）；下载子目录文件保留相对路径落地到 download |
| **v0.1.3** ✅ 已交付 | 多文件下载列表按下载先后顺序稳定排列（start 时间 + ID 排阻），不再跳动 |
| **v0.1.4** ✅ 已交付 | 左侧在线机器列表按 IP 数值升序稳定排序（不再跳动） |
| v0.2.0 | 多文件批量下载、目录打包下载（.zip）、下载队列管理/取消 |
| v0.3.0 | 上传（拖拽/多文件）、删除远程文件、搜索/筛选、限速 |
| v0.4.0 | 文件夹递归共享、传输历史、断网重试、手动添加 IP（广播不可达时） |
| v0.5.0 | 点对点文本消息、可选口令鉴权、暗色/移动端适配 |

## 三、验收标准（v0.1.0）

1. 同网段两台机器各起一个实例，能在对方机器列表里看到彼此。
2. 点击对方能看到 upload 目录的文件名/大小/修改时间。
3. 下载大文件落盘到本机 download 目录，进度条实时推进。
4. 中断后重新下载能断点续传（Range 生效）。
5. 相同文件重复下载被秒传跳过。
6. 人为损坏文件后下载能标红「损坏」。
